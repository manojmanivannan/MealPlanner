# ADR 0005 — Responsive & accessibility audit (T8 gate)

- **Status:** Decided — 2026-08-19. This is the gate before the map's destination (a clean, accessible redesign spec) is considered reached. Per the map's plan-first preference, this ticket resolves a *decision* (a list of gaps + a disposition for each) — it is not the execution of the fixes. Execution graduates to fix tickets.
- **Decides:** GitHub Issue #22 (T8 — Responsive & accessibility audit).
- **Audits:** the T4–T7 built artifacts — `frontend/src/pages/weekly-planner.js` + `index.html` (#18), `frontend/src/pages/recipe-hub.js` + `recipe-hub.html` (#19), `frontend/src/pages/ingredients.js` + `ingredients.html` (#20), `frontend/src/pages/shopping-list.js` + `shopping-list.html` (#21) — plus the shared shell they all mount (`src/layout.js`, `design/tokens.css`, `design/components.css`, `src/components/{modal,toast}.js`) since every audited page inherits it.

## Context

T1 (#15) locked the token layer with a stated WCAG-AA target and a day-color usage contract ("the 7 day colors are NEVER used as text — only as dot / border / chip fill"). T2 (#16) shipped the Vite build + the JS-injected shared header/auth. T3 (#17) shipped the `.mp-*` catalog with `modal.js` (focus trap / ESC / aria / scroll lock / focus restore) and `toast.js` (role=alert/status). T4–T7 adopted those, each ADR deferring automated a11y/keyboard/responsive verification to "the T8 gate ticket's job." This is that gate.

The grilling brief (#14) set the targets: **WCAG AA** contrast (the call-out was *macro text on day-accent cards*), **keyboard** nav (tab order, modal focus trap/restore, ESC), **aria** on modals/tabs/toggles, **mobile** (planner stacks, modals full-screen, touch targets ≥44px), and **reduced-motion** respect.

Method: static read of the four page modules + shared shell + token/component CSS, verified by computing the actual WCAG 2.1 contrast ratios (Python sRGB → relative-luminance → (L₁+0.05)/(L₂+0.05)) for every color pair the prototypes render, and by grepping for the a11y primitives (skip link, `role="img"`, `aria-labelledby`, menu Escape, target sizes). No browser automation harness exists in the repo (per the T1–T3 precedent), so this is a manual + computed audit, not an axe/lighthouse run.

## Decision

The T4–T7 redesigns **meet the AA target on the headline concern and clear most of the rest by construction.** Eight gaps survived verification. None are severe; the catalog is sound enough that every gap is a localized, code-only fix. Per the ticket, each gap is dispositioned here and graduates to a fix ticket rather than being executed inline (plan-first; execution is separate). The spec's "each gap *may* graduate to its own fix ticket" is permissive, so the eight gaps are grouped by domain into **two proposed fix tickets** (issue creation pending — they are fully specified here as T9/T10 so the decision is captured regardless):

- **T9 — Accessibility fixes (contrast, keyboard, aria):** C1, K1, K2, A1, A2, A3, A4.
- **T10 — Responsive & touch-target fixes:** M1, M2.

### What passes (verified)

**Contrast — the headline concern is satisfied.** Macro text on day-accent cards renders on the *neutral* card surface, not on the day color: the day shows only as a 3px top border (`.mp-card-day`) + a `.day-dot` + a soft badge (`.mp-badge-day-soft`), per the locked T1 contract. `text-muted` (#6b7280) on the white surface is **4.83:1** and `text-secondary` (#4a5160) is **7.96:1** — both clear AA. The old `text-stone-500`-on-`#fff6b7`-pastel-fill failure (the reason this ticket exists) is structurally gone. Computed ratios that **pass AA** (≥4.5:1 normal, ≥3:1 large): accent `#0f766e` on white 5.47:1; accent-subtle badge (`#0f766e` on `#d1f5ee`) 4.69:1; every day chip — white-on-day 5.02–7.90:1 (mon/tue/wed/thu/fri/sat/sun); every status badge — white-on-danger 5.18, -warning 5.02, -success 5.48; and the whole dark theme — accent `#2dd4bf` on surface 8.69:1, dark text-muted 4.56:1, dark accent-subtle badge 6.35:1, dark day chips (ink `#0f1320` on the -400 day hues) 6.80–11.09:1.

**Keyboard — modals and tabs are correct.** `modal.js` traps Tab/Shift+Tab within the panel, closes on Escape + backdrop click, restores focus to the opener, and locks body scroll (ref-counted for stacking). The recipe-hub category tabs use the ARIA tabs pattern: arrow-left/right + Home/End + roving `tabindex` + `aria-selected`/`aria-controls` (`recipe-hub.js:321`). Live search re-renders only the grid so the toolbar input keeps focus (`recipe-hub.js:366`, `ingredients.js:304`, `shopping-list.js:296`). The shopping-list check-off restores focus to the toggled checkbox after the re-render so keyboard/SR users keep their place (`shopping-list.js:279`).

**ARIA — the load-bearing pieces are correct.** Modals: `role="dialog"` `aria-modal="true"` `aria-labelledby` (title set via `textContent`, XSS-safe) + `aria-describedby` (`modal.js:103-106`). Toasts: `role="alert"` for error/warning, `role="status"` for success/info (`toast.js:65`). Shopping-list progress bar: `role="progressbar"` + `aria-valuenow/min/max` + `aria-label` (`shopping-list.js:163`). Recipe-hub tablist: `role="tablist"/"tab"` + `aria-selected` + `aria-controls`. Minerals group: native `<details>/<summary>`. Forms: labelled inputs/selects, `aria-invalid` + `.mp-error-text`, required indicators.

**Mobile — the big wins landed.** The planner grid stacks 1→2→3→4 columns (`index.html:31`); day cards are full-width on mobile. Modals go full-screen at ≤640px (`.mp-modal` loses radius/border, becomes the page) per `components.css:511-524`. Page toolbars wrap with `flex-col sm:flex-row`. `html { font-size: 100% }` honors the browser text-size preference; `color-scheme` is set per theme.

**Reduced motion — fully respected.** A global `@media (prefers-reduced-motion: reduce)` in `tokens.css:342` collapses every transition/animation to 0.01ms and sets `scroll-behavior: auto`; `toast.js` additionally short-circuits its leave animation under reduced motion (`toast.js:52`). Spinners/skeletons collapse to a static frame, which is the intended behavior. **No gap.**

### Gaps (each graduates to a fix ticket)

**C1 — `text-muted` on `--bg-subtle` fails AA (4.24:1).** `--text-muted` `#6b7280` is **4.24:1** on `--bg-subtle` `#eef0f5` (below the 4.5:1 AA threshold for normal text). The T1 token comment over-claimed "~4.6:1" — that holds on the white surface (4.83:1), not on `bg-subtle`. Surfaced in the T5 add/edit-recipe modal's ingredient multi-select panel, which is `bg-subtle`: the per-row serving-unit suffix `.ing-unit` (`recipe-hub.js:648`) and the "No ingredients available" empty hint (`recipe-hub.js:638`). (Same pair also reads 4.06:1 on `bg-sunken`, used for disabled inputs — disabled controls are exempt from 1.4.3, so that's not a failure.) *Disposition: T9. Fix: use `text-secondary` (6.98:1 on bg-subtle) for text on bg-subtle surfaces, or darken `--text-muted` to ~`#5f6672` (≥4.5 on bg-subtle) globally with an ADR-0001 token amendment.*

**K1 — No skip-to-content link.** Every page mounts the nav header (4 nav links + the user menu) before `<main>`, and no `<main>` has an `id`. A keyboard user Tabs through the whole header on every page load before reaching content. *Disposition: T9. Fix: add a visually-hidden-until-focused "Skip to main content" link as the first focusable element in the shared `headerHTML` (`layout.js:32`), targeting `<main id="main">` (add the id to the four page shells).*

**K2 — User-menu dropdown isn't keyboard-complete.** The menu button has `aria-haspopup` + `aria-expanded` and the panel has `role="menu"`/`role="menuitem"`, and click-outside closes it (`layout.js:61-69`), but **Escape doesn't close it** and **opening it doesn't move focus into the menu** (the menuitem isn't reachable by arrow keys). *Disposition: T9. Fix: on open, focus the first menuitem; on Escape, close and return focus to the button; optional roving-tabindex arrow nav for the menu pattern.*

**A1 — Recipe-hub tabpanel is mis-labelled on first load.** `#recipe-grid` has `aria-labelledby="hub-tabs"` (`recipe-hub.html:51`) — pointing at the *tablist container*, not the selected tab. `wireTablist.select()` sets it correctly (`recipe-hub.js:329`) but only on user interaction; on first load the tabpanel is labelled by the tablist. *Disposition: T9. Fix: at the end of `renderTabs()`, set `grid.setAttribute('aria-labelledby', 'hub-tab-' + activeCategory)` so the initial state matches the post-click state.*

**A2 — Vegetarian/non-veg dot has no accessible role.** The 14px dot on recipe cards is a `<span>` with `aria-label` and `title` but **no `role`** (`recipe-hub.js:286`). Per ARIA, `aria-label` on a generic `<span>` (no role) is ignored by most screen readers, so the veg/non-veg distinction — conveyed by color alone otherwise — isn't reliably announced. (The detail modal already uses text badges; only the card uses the dot.) *Disposition: T9. Fix: add `role="img"` (keep the `aria-label`), or replace the dot with the visible text badge the detail modal uses.*

**A3 — Pantry switch track isn't hidden from AT.** The "In pantry" `.mp-switch-track` in the ingredients card has no `aria-hidden` (`ingredients.js:247`), unlike the shopping-list "Hide checked" switch which marks its track `aria-hidden="true"` (`shopping-list.html:32`). The track is a visual duplicate of the native checkbox state; the accessible name comes from the "In pantry" label text, so this is cosmetic, not a naming failure. *Disposition: T9. Fix: add `aria-hidden="true"` to the decorative track for parity.*

**A4 — Error/loading states aren't announced.** When a fetch fails, the page renders an `.mp-state-error` card (`weekly-planner.js:230`, `recipe-hub.js:231`, `ingredients.js:181`, `shopping-list.js:183`) with **no `role="alert"` / `aria-live`**, so a screen-reader user on a failed load isn't notified — the visual change is silent to AT. (Toast errors *are* announced, but the error state replaces the whole grid, not a toast. An aria-live gap, so it sits in the A-group.) *Disposition: T9. Fix: add `role="alert"` to the error-state container on all four pages.*

**M1 — Touch targets below 44×44px (notable).** The primary actions on every card (Clear/Change/Add/Edit/Delete/Show/Assign/Copy) and the modal close are smaller than the brief's ≥44px target. `.mp-btn-sm` is ~24px tall (14px font + 4px vertical padding, `components.css:63`); `.mp-btn-icon` is 36px (28px for the `mp-btn-sm` variant, used by the modal close, `components.css:135`); the in-chip recipe remove × reuses `.mp-toast-close` (a 14px SVG, ~16px hit area, `components.css:396`). *Disposition: T10. This reopens the T3 catalog sizes (locked) → a design decision, so it's a ticket, not an inline fix. Fix: raise the minimum hit size to 44px on `@media (pointer: coarse)` (a `min-height`/`min-width` bump on `.mp-btn-sm`/`.mp-btn-icon`/`.mp-toast-close` for touch) so the desktop density is preserved while mobile gets compliant targets.*

**M2 — Nav header doesn't collapse on narrow viewports.** The 4 nav links + user menu sit in a single non-wrapping `flex justify-between` row (`layout.js:34-44`) — ~420px of links + the user menu, which overflows/shrinks on a 360px phone with no hamburger. *Disposition: T10. Fix: collapse the nav into a menu under ~640px, or let it wrap; touches the T2 shared layout.*

## Consequences

- **Positive:** The audit confirms the redesign's central a11y bet paid off: the headline macro-contrast failure is fixed *by construction* (neutral surface + token text, day color as accent only), and the reusable `modal.js`/`toast.js`/tab-pattern were built correctly — focus trap, ESC, aria, restore, reduced-motion, and the ARIA tabs pattern all hold under inspection. Eight localized gaps, all code-only, none structural; the catalog doesn't need rethinking, only tightening.
- **Negative:** Two of the gaps (M1 touch targets, M2 responsive nav) touch components the prior ADRs declared "locked" (T3 catalog sizes, T2 layout), so they need a short design decision (preserve desktop density vs. uniform 44px; collapse vs. wrap) rather than a blind patch — the cost of the plan-first/locked-catalog discipline. The contrast miss (C1) shows the token comment over-claimed a ratio that only holds on one surface; the token layer's "AA by construction" promise needs the one `bg-subtle` caveat documented or the muted token nudged darker.
- **Follow-ups:** **T9 (a11y fixes: C1/K1/K2/A1/A2/A3/A4)** and **T10 (responsive + touch: M1/M2)** are the two proposed graduated fix tickets — fully specified here, with issue creation pending (T9/T10 are the placeholder titles). Once T9 + T10 land, the map's destination — a clean, accessible redesign spec — is reached, and the rollout can switch `frontend/Dockerfile` + nginx to `frontend/dist/` and delete `legacy.css` + the legacy `frontend/html/*.js` page-content files (the deferred rollout item from #14). An automated a11y harness (axe/playwright) is still absent; adding one is a worthwhile future ticket but was explicitly out of scope for the plan-first phase.
- **Blocked-by / Blocks:** Blocked-by #18 (T4 planner), #19 (T5 recipe hub), #20 (T6 ingredients), #21 (T7 shopping list) — the artifacts audited. Blocks the two graduated fix tickets (T9, T10) and the map's destination (#14).

## Verification

- `npm run build` (in `frontend/`) succeeds; `npm test` passes (87/87, the T5–T7 logic suites). No code changed in this ticket — the audit is a decision doc.
- Contrast ratios computed with a sRGB-relative-luminance script over the exact token values in `design/tokens.css` (light + dark). Cited ratios reproduced above; the only sub-4.5:1 normal-text pair that actually renders is `text-muted` on `bg-subtle` (C1) — every other audited pair clears AA.
- Gap citations verified by grep against the built sources: veg-dot span without role (`recipe-hub.js:286`), no skip link / no `<main id>` in any page shell, tabpanel `aria-labelledby="hub-tabs"` (`recipe-hub.html:51`), menu without Escape (`layout.js`), error states without `role="alert"` (all four modules), `.mp-btn-sm`/`.mp-btn-icon`/`.mp-toast-close` sizes (`components.css:63,135,396`), non-collapsing nav (`layout.js:34`).

**Scope note on the test suite:** as with T1–T7, the repo's test suite is the Python/pytest backend stack (`tests/`, needs Docker/testcontainers), which has zero overlap with these frontend-only artifacts and was not re-run. The frontend has no browser-automation/a11y harness yet; this audit is manual + computed, consistent with the T1–T3 precedent and the explicit "automated verification is the T8 gate's job" deferral in ADRs 0001–0004.
