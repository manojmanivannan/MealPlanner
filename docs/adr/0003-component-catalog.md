# ADR 0003 — Component catalog (restyled primitives + states + auth form)

- **Status:** Proposed — 2026-08-19. Ready to lock on review of the catalog (`frontend/catalog.html`, served by the T2 Vite build). Per the map's plan-first preference, this is a decision + artifact to react to, not a final deliverable.
- **Decides:** GitHub Issue #17 (T3 — Component catalog)
- **Supersedes:** the legacy `insertAdjacentHTML` modals (no focus trap / ESC / aria) in `frontend/html/{weekly-plan,recipe-hub,ingredients}.js` and the silent `console.error` / blocking `alert()` feedback (PDF-export path in `index.html`, recipe/ingredient alerts). `src/legacy.css` stays in the build for continuity until T4–T7 migrate the page-content JS onto these classes.

## Context

T1 (#15) established the token layer and T2 (#16) the Vite MPA + compiled-Tailwind build + shared layout. What is missing is the restyled primitive set itself and — critically — the three behaviors the grilling brief flagged as the app's worst gaps: (1) modals are HTML-string injection (`insertAdjacentHTML`) with no focus trap, no ESC, no aria, and no body-scroll lock; (2) errors are silent (`console.error`) or blocking (`alert()`); (3) the empty/loading/error states don't exist — failures render as blank space. This catalog is the single react-to surface that defines how every primitive looks and behaves in the new system, and it unblocks the four page-redesign tickets (#18–#21). The map notes the catalog must be reacted to and then the component decisions *locked*.

## Decision

Adopt a token-driven component-primitive layer as the single source of truth (`frontend/design/components.css`) with a catalog reference (`frontend/catalog.html`, a Vite entry) and two reusable behavior modules (`frontend/src/components/modal.js`, `toast.js`). The system is:

- **Namespaced `.mp-*` classes, in `@layer components`.** Every primitive is `.mp-*` so it cannot collide with Tailwind utilities or the legacy `.clay-*` / `.meal-card` classes. The whole file is wrapped in `@layer components`, so Tailwind utilities (in the higher `utilities` layer) win when both apply — a page can always override a component's padding/width/spacing with a utility without a specificity fight. Component classes own the *look* and interactive states; utilities own layout. `styles.css` imports it after `tokens.css` and before `legacy.css`.
- **Buttons — primary/secondary/ghost/danger + sizes + states.** Four variants (primary = teal `--accent`; secondary = neutral surface + strong edge; ghost = transparent until hover; danger = solid `--color-danger`). Three sizes (sm/default/lg) + `.mp-btn-block`. Full state set: hover, `:focus-visible` (the T1 ring), active, `:disabled` (dim + no pointer), and `data-loading="true"` + `aria-busy` (a CSS spinner via `::after`, label hidden by opacity). The danger button reuses `--accent-fg` for its label — white in light, dark-ink in dark — because both clear AA on the status-red surface (no new token needed). An icon-only variant (`.mp-btn-icon`) and a danger-outline variant are included.
- **Cards — neutral surface + day accent, never a full-card day fill.** `.mp-card` is a flat surface with a hairline border; `.elevate` adds the single T1 shadow; `.interactive` lifts on hover and is keyboard-focusable. The day-accent variants are `.mp-card-day` (3px top edge) and `.mp-card-day-bar` (4px left bar) — the day color is the *border*, never the background, per the locked T1 contract. The day shows in the header as a `.day-dot` and as a count in a `.mp-badge-day-soft` soft-tint badge.
- **Inputs/selects/checkboxes.** A `.mp-field` groups `.mp-label` (with `.mp-req` for required) + control + `.mp-help` / `.mp-error-text`. `.mp-input`, `.mp-select`, `.mp-textarea` share the token-driven look: `--radius-md`, `--border-default`, `--bg-surface`, the T1 focus ring, and an `aria-invalid="true"` danger border + danger-tinted ring. `.mp-select` is native with a custom chevron (inline SVG data-uri). Checkboxes/radios stay **native** with `accent-color: var(--accent)` + a focus ring (semantics + keyboard free); a `.mp-switch` pill toggle and `.mp-check` label wrapper are provided.
- **Modals/dialogs — accessible, the explicit gap.** `.mp-modal-overlay` + `.mp-modal` (header/title/close, body, footer) is the visual shell. `frontend/src/components/modal.js` owns the lifecycle: `role="dialog" aria-modal="true" aria-labelledby` (+ `aria-describedby` when a body id is set), focus moved to the first real control (skipping the dismiss X, else the panel), **Tab/Shift+Tab trapped** within the panel via explicit handling (deterministic cycle, not browser default), **Escape** closes, **backdrop click** closes (panel click doesn't), focus is **restored** to the caller, and **body scroll is locked** while open (with a scrollbar-gap padding compensation). **Full-screen on mobile**: at ≤640px the panel becomes the page (no radius, no border, `min-height: 100vh`, slide-up animation), matching the a11y assumption in the grilling brief. The `size` arg maps to width tiers — `.mp-modal-sm` (22rem) / `.mp-modal-md` (32rem, default) / `.mp-modal-lg` (48rem) — all overridden to full-width on mobile. `openModal({ title, body, footer, size, returnFocus, onClose })` returns a `{ close }` controller — in-modal action buttons must call `ctrl.close()`, never remove the overlay by hand, or focus/scroll are not restored.
- **Tabs — roving tabindex.** `.mp-tablist` + `.mp-tab[aria-selected]` + `.mp-tabpanel`. Arrow Left/Right move between tabs, Home/End jump to the ends, the selected tab carries `tabindex=0` and the accent underline. The roving-index logic is one shared `wireTablist(tablist, onSelect)` helper in catalog.js, used by both the demo tabs (panel switching) and the auth tabs (form switching) — so there is a single tab pattern for T4–T7 to copy, inlined rather than shipped as a third module.
- **Badges/pills.** `.mp-badge` (caption) + `.mp-badge-lg` (pill). Neutral by default; `.mp-badge-accent` (brand), `.mp-badge-success/warning/danger` (status, label in `--accent-fg`), `.mp-badge-outline`. Day badges: `.mp-badge-day` (solid `--day-color`, label `--day-fg`) and `.mp-badge-day-soft` (soft tint, neutral-ink label).
- **Toasts — the alert()/console.error replacement.** `.mp-toast-region` (fixed, `z-toast`, stacked) + `.mp-toast` (icon + title + message + dismiss). `frontend/src/components/toast.js` exposes `toast.show(msg, { variant, title, duration })` plus `.success/.error/.warning/.info` shortcuts. role is tuned per variant — `role="alert"` for error/warning, `role="status"` for success/info — and each toast's role is self-announcing, so the region carries no `aria-live` (a region-level `aria-live="polite"` would contradict the assertive alerts). Auto-dismiss after 5s, pause on hover, manual dismiss, and exit animation that respects `prefers-reduced-motion` (the T1 global motion rule collapses durations).
- **Empty / loading / error states — the #1 planner UX gap.** A `.mp-state` centered column (icon + title + description + optional action). `.mp-state-error` tints the icon danger. Loading is a standalone `.mp-spinner` or in-place `.mp-skeleton` shimmer lines (the content-shape placeholder for lists/cards). Each state carries a clear one-line explanation and an action (Add / Retry) — today's blank-or-silent failure is replaced with a recoverable surface.
- **Auth screen — the form showcase.** The restyled login/signup is section 09 of the catalog: `.mp-btn` tabs (with the same roving-tab arrow handling), `.mp-field` + `.mp-input` with inline `role="alert"` error text, a `data-loading` submit that spins, and a success toast on completion. It is the reference the real `welcome.html` adopts; this ticket does **not** rewrite `welcome.html` (auth is not in the T4–T7 page set), which keeps scope bounded and the deployed gate unchanged.
- **Theme + a11y by construction.** Every color is a T1 variable, so light/dark + the manual toggle all work without per-component overrides. Focus is the T1 `:focus-visible` ring throughout. Motion defers to the T1 reduced-motion rule. The catalog ships its own theme toggle (Light/System/Dark) persisted under `mp-theme`.

## Consequences

- **Positive:** One reusable primitive set unblocks T4–T7 at once; the two worst a11y/UX gaps (modals, feedback) have a correct, reusable implementation rather than four per-page rewrites; states get a real pattern instead of blank failures; dark mode and focus work by construction because everything resolves to T1 tokens; the `.mp-*` namespace + `@layer components` keeps utilities authoritative for layout, so pages compose freely without specificity conflicts.
- **Negative:** During rollout the legacy `insertAdjacentHTML` modals and `alert()` calls still exist in `frontend/html/*.js` (served by the current nginx/Docker) until T4–T7 migrate them onto `modal.js` / `toast.js` — so the two patterns coexist until then, same as the legacy clay classes. The component classes add CSS weight to the shared bundle (offset by the eventual removal of `legacy.css`). The danger button reusing `--accent-fg` is a small semantic stretch (documented above) chosen to avoid re-opening the locked T1 token set for a status-foreground token.
- **Follow-ups:** T4 (#18 weekly planner), T5 (#19 recipe hub), T6 (#20 ingredients), T7 (#21 shopping list) adopt these classes and swap their `insertAdjacentHTML` modals for `modal.js` and their `alert()`/`console.error` for `toast.js`; once all four land, `legacy.css` and the clay classes are removed. **Automated a11y/keyboard + responsive verification is deferred to T8 (#22, the audit gate)** — this catalog was verified by build + manual inspection (see Verification), consistent with the T1/T2 precedent; introducing a browser test runner (Playwright) is T8's call, not this prototype's.
- **Blocked-by:** #15 (T1 tokens — consumed directly), #16 (T2 build — the catalog is a Vite entry on the compiled Tailwind stack). **Blocks:** #18, #19, #20, #21 (the page redesigns consume the catalog).

## Verification

`npm run build` (in `frontend/`) produces `frontend/dist/`:

- A new `catalog.html` entry builds as a `rollupOptions.input` and references only hashed `/assets/*` — `catalog-*.js` (which bundles `modal.js` + `toast.js` + `bootstrap.js`) and the shared `bootstrap-*.css`. No `cdn.tailwindcss.com`, no `fonts.googleapis.com` (confirmed by grep of `dist/`).
- The compiled CSS contains the `.mp-*` primitive classes resolving to T1 variables — `.mp-btn`, `.mp-card`, `.mp-modal`, `.mp-toast`, `.mp-state`, `.mp-input`, `.mp-switch`, `.mp-badge`, `.mp-skeleton`, `.mp-spinner` — so light/dark + the manual toggle drive them at runtime.
- The existing four pages (`index`, `recipe-hub`, `ingredients`, `welcome`) still build unchanged; `legacy.css` and the clay classes survive in the bundle, so the reused page-content JS renders unchanged.

`npm run dev` serves `catalog.html` (200) and every module (`src/components/modal.js`, `src/components/toast.js`, `src/bootstrap.js`, `src/styles.css`, `design/components.css`, `design/tokens.css` all 200); the catalog's theme toggle, tabs (arrow-key + Home/End), toast triggers, modal triggers (focus-in, Tab trap, ESC, backdrop-click, focus restore, scroll lock), and the auth form (tabbed login/signup, inline validation, loading submit, success toast) drive the live page.

**Scope note on the test suite:** the repo's existing test suite is the Python/pytest backend stack (`tests/`, needs `pytest` + `fastapi.testclient` + `testcontainers` Postgres/Docker), which is not installed in this environment and has zero overlap with these frontend-only changes — so it was not re-run here. The frontend has no JS test runner yet; automated a11y/keyboard verification is the T8 gate ticket's job.
